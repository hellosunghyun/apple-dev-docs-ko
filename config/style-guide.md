# Apple Dev Docs KO Translation Style Guide

- Use concise Korean technical documentation style.
- Keep API symbols, type names, method names, paths, URLs, code, framework names, and product names unchanged.
- Prefer `합니다` endings.
- Do not add explanations that are absent from the source.
- Keep segment-level alignment where possible because the site can show the original sentence for each Korean segment.
- Use the official Apple documentation as the final source of truth when a translation is ambiguous.
